# 网络与参数设置开发增量

## 本轮可用范围

- 主界面“系统设置”显示当前 IPv4、RTSP 地址和真实编码规格 H.264 1280x720。
- RTSP 端口支持 1024~65535，保存在 `/etc/lawrec-rtsp-port`。
  重启 UI 后生效；当前 worker 和监听端口不受保存操作影响。
- “WiFi互传”页支持输入 WPA2-PSK 热点 SSID/密码，第二次按 Save 确认替换
  `/etc/wpa_supplicant.conf` 中全部已有热点。当前连接保持不变，板子下次启动后
  由既有 S45wifi 使用新配置关联并申请 DHCP。
- SSID 按 UTF-8 字节长度校验为 1~32；密码支持 8~63 位可打印 ASCII，
  暂不支持引号、反斜杠、64 位十六进制 PSK、企业认证或 WPA3-only。
- 配置采用同目录临时文件、fsync、rename、目录 fsync；凭据文件权限 0600。
  不调用 shell，不记录凭据；非法输入不会替换旧配置。
- 只读根文件系统会显示保存失败，不自动 remount。目录 fsync 失败时，
  rename 可能已完成，但不能保证断电持久性，必须检查文件后重试。
- 首页不再虚报 1080P60 或 WiFi 已就绪。设置页面暂用英文以避免缺字。

## 验证

### 扫描与状态增量

- 新增 `lawrec_network` C API，通过 Unix datagram socket 直接调用 supplicant，
  不启动 wpa_cli/demo，不使用 shell。默认接口 `/var/run/wpa_supplicant/wlan0`。
- UI 的 Status 查询关联状态、当前 SSID/IP；Scan 发起后台扫描并等待
  `CTRL-EVENT-SCAN-RESULTS` 后读取列表。Next AP 浏览，Use SSID 只填入输入框。
- 最多显示 24 个可表示的热点；隐藏 SSID、控制字符 SSID、非法扫描行被过滤。
  扫描可显示开放或企业热点，但保存功能仍仅支持 WPA2-PSK。
- 命令响应超时 2 秒，扫描事件超时 12 秒。所有等待在后台线程，退出支持取消并 join；
  不会让 LVGL 等待网络响应。记录请求类型、错误码和数量，不记录密码。
- 私有临时目录保护客户端 socket，操作完成后关闭并清理。
- 已通过 C 盘 PowerShell SSH 只读确认板端存在上述 socket；没有更换板端程序，
  没有执行在线切网，也没有把此检查当作实板扫描验收。
- Docker `out/network-tests.log` 覆盖正常状态、提前到达的扫描事件、解析、忙碌拒绝、
  超长响应、超时、退出取消；编译日志为 `out/network-build.log`。

- `bash tools/test.sh`：Docker 中运行设置、存储、Annex-B、触控、回放模拟测试。
- 设置测试覆盖重启生效、非法端口、损坏文件回退、符号链接拒绝、凭据权限、
  配置注入拒绝和失败时旧配置保持不变。
- `bash tools/build.sh little`：Docker 交叉编译，日志 `out/settings-build.log`。
- 未上传或修改当前板端网络，也未验证新页面的实际触摸、字形、布局和 WiFi 重连。

## 后续执行清单

### DHCP 更新增量

- 新增 Renew IP，第二次确认才执行；可能导致 SSH/推流中断，不自动执行。
- 要求当前关联状态 COMPLETED；检测到正在运行的 udhcpc 或 S45wifi 启动 worker 时拒绝，
  不使用 killall，不预先清空网卡地址或全局默认路由。
- 使用 `posix_spawn` argv 调用 `/sbin/udhcpc -i wlan0 -f -q -n -t 4 -T 3`，
  利用系统既有 DHCP hook 配置地址，详细日志 `/tmp/lawrec-dhcp.log`。
- 独立进程组，20 秒总超时，停止时 TERM/KILL 并 waitpid 回收；UI 网络线程退出可取消。
- 成功退出后重新检查关联及 IPv4 地址。不把“子进程启动”当作租约成功。
- Docker 进程测试覆盖成功/失败退出、程序不存在、超时、取消与无遗留子进程。
- 实板 DHCP 更新未执行；仍未实现在线换热点、失败回滚及长期租约自动续期管理。

1. 网络控制 API：控制 socket、后台扫描和状态查询已接入；继续实现关联状态机、连接超时、
   DHCP 租约更新、断线回滚。现有 S45wifi 有全局 killall 和删除默认路由行为，
   不能直接复用为运行期切网 API。在线切网须显式确认 SSH 断开风险。
2. 参数：统一持久化快照及版本迁移，再加入存储目录、码率、帧率等已由大核支持的参数；
   不展示尚未接入硬件的假开关。本轮只开放 RTSP 端口。
3. 音频：核实板级麦克风、AI/AENC/VB，处理每步错误和逆序释放，再接入 RTSP、MP4
   以及回放音轨。当前仅增加音频回调空指针/长度/异常防护，没有开放音频功能。
4. RTSP 与录像并发：优先评估一个编码器分发到两个有界队列，消费者独立状态、
   首 IDR 等待、背压和引用计数；最后一个消费者停止后才释放编码资源。
   不能仅删除 control 和 media 层互斥；当前仍明确互斥。
5. 板测：先配置保存与重启，再测试切网失败恢复、音视频同步、并发启停及慢 SD 卡。

### 在线换热点事务增量

- Connect 二次确认后调用控制 socket，不执行 shell，不自动保存配置。
- 先拒绝与开机 WiFi worker/现存 DHCP 客户端竞争，再读取原有网络 ID、当前连接及使能状态。
- 新建 disabled profile，设置 SSID/PSK/WPA2/隐藏热点扫描，SELECT 后等待对应 network id
  的 COMPLETED（最多约 32 秒），再申请 DHCP 并验证关联/IP。
- 设置失败清理新 profile；选择、关联、DHCP 失败尝试重新选择旧网络、删除新 profile、
  恢复旧 enabled/disabled 状态、重新关联并申请旧网 DHCP。
- 原始错误与 rollback_error 分开显示和记录；恢复失败不报告“旧网络已恢复”。
- UI 退出时仍做有界恢复，不因为取消标志直接跳过回滚。因此在切网期间退出 UI
  可能等待旧网关联和 DHCP，不能按普通扫描取消的耗时预期处理。
- 每条切网控制命令独立 socket，超时后的迟到响应不会被当作回滚命令成功。
- ADD_NETWORK 响应丢失可能留下未知 ID 的 disabled profile：明确报恢复不确定，
  不猜测 ID 删除其他配置。需要 STATUS/LIST_NETWORKS 或重启 supplicant 后核对。
- 成功后旧 profile 仍在内存但被禁用；Save WiFi 才替换下次启动配置。
  在线换网与配置持久化是两个明确动作，不把关联成功当作持久化成功。
- Docker 事务测试覆盖每个 SET/SELECT 步骤失败、关联/DHCP 失败、取消、恢复失败、
  原本未连接及异常抛出。实际切网与回滚尚未在板端执行，SSH 网络未改动。
- 尚需统一长期租约管理、参数配置扩展以及端到端板测；静态 IP/DNS 尚未实现。

这些是网络设置开发增量，不代表“完整网络、音频、并发”已交付。

## 媒体参数配置升级

新配置 `/etc/lawrec-media.conf` 格式：

```ini
version=1
rtsp_port=8554
video_bitrate_kbps=4000
record_segment_seconds=0
```

- 端口范围 1024~65535，应用允许的视频目标码率范围 1000~8000 kbps；实际编码器
  输出码率/画质仍待板测，不把 CBR 目标值当作实测值。
- 版本、重复/未知字段、缺少字段和非法值均检查。文件损坏回退默认并记录错误；
  旧 `/etc/lawrec-rtsp-port` 仅在新文件不存在时用于兼容迁移。
- 两个字段同文件原子写入，避免分别保存造成部分成功。配置文件同步仍遵守 fsync/rename
  边界；rename 后目录同步失败会报错，但文件可能已改变。
- 主程序启动时固定快照。Save 不热改 VENC/RTSP；重启 UI 后，RTSP 和录像初始化的
  `rc_attr.cbr.bit_rate` 使用同一值，各自输出日志确认请求参数。
- Settings 页面显示当前生效值，编辑框显示已保存值；Defaults 只填入默认草稿，
  仍须按 Save 才持久化。只读/损坏配置错误可见，不自动挂载或覆盖。
- 未开放分辨率/帧率/音频假开关，存储、分段等参数后续与其实现同步加入。
- 分段增量：新增可选 `record_segment_seconds`（0 关闭，60~3600 秒）。旧 v1 文件
  未包含此字段时按关闭处理；UI Segment 按钮循环选择 0/60/180/300/600 秒。
  仍为保存后重启 UI 生效，设置值是请求切段的门槛，不保证精确秒数。
- 本轮证据：`out/media-settings-build.log` 和 `out/media-settings-tests.log`。
  测试包括升级、非法字段、未知版本、端口修改保留待生效码率、失败不改变旧配置、
  重启读取及当前进程快照不变；没有上板更新或生成新镜像。
