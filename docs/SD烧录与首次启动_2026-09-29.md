## Windows 烧录

资源管理器打开：

```text
\\wsl$\Ubuntu\home\atlantis\lawrec\out\releases
```

使用烧录工具选择上述 `.img`，确认目标是 SD 卡后写入并执行校验。
写入会覆盖 SD 卡现有分区和数据，请先备份。不是把 img 复制进 SD 文件夹。
若工具不能访问 WSL 路径，先将镜像复制到 Windows 本地目录。

## 首次启动

大核串口执行，使用镜像内的程序，不依赖首次不存在的 `/sharefs/lawrec.elf`：

```sh
/bin/fastboot_app.elf /bin/retinaface.kmodel /bin/mbface.kmodel
```

看到 `preview backend ready` 后，在小核 SSH 执行：

```sh
mount | grep sharefs
df -h /sharefs
```

确认 `/sharefs` 是 SD 的第 4 分区而不是根目录下的空挂载点，再执行：

```sh
mkdir -p /sharefs/lawrec_records
/app/lawrec/ui/ui >/tmp/lawrec.log 2>&1 &
```

观察日志：

```sh
tail -f /tmp/lawrec.log
```

当前 UI 自启动标志未启用。调试阶段不必操作 `/etc/init.d/S99lawrec start`；
该脚本只有存在 `/etc/lawrec-ui.autostart` 才启动 UI。

## 存储和后续更新

镜像第 4 分区目前为 256 MiB，未自动占用整张 SD 卡。录像保留 128 MiB
安全余量，长录像测试前需要备份并扩容数据分区；扩容不要求重烧系统。
不要在未确认分区和挂载状态前执行格式化命令。

后续业务更新走 SSH/SCP：小核替换 `/app/lawrec/ui/ui`，大核传入
`/sharefs/lawrec.elf` 后手动运行。更新前停止相关程序，不覆盖正在运行的 ELF。
若修改内核、设备树或启动固件，则不能承诺永远只更新业务 ELF。
