# 显示恢复与设备维护

## 本轮问题与修复

回放图层切换原来只有一个布尔值，开启失败时恢复预览层的返回值没有检查。
恢复失败可能仍被描述为显示空闲。本轮把切换收敛到大核
`LawrecDisplayController`，保留原来的 1280×720 输入、480×270 输出、y=200、
YVU420 和 stride 参数，没有修改连接器、时钟、PHY、面板命令或 VTTH。

| 操作 | 当前行为 |
| --- | --- |
| 开启回放图层 | 先标记占用，再配置 layer0、关闭 layer1、开启 layer0 |
| 开启失败 | 尝试关闭 layer0、恢复 layer1；保留首次错误，记录失败步骤和回滚结果 |
| 回滚失败 | 继续标记占用，拒绝新开启，不假装空闲 |
| 恢复显示 | 明确关闭 layer0、恢复 layer1；两步都成功才解除显示占用 |

现有回放 worker 的 display-off 也使用同一恢复方法。当前回放流程及图层参数
不变，没有新增线程或服务。状态仍是 SDK 调用结果及软件标记，不是硬件
寄存器读回或摄像头出帧证明。

## 设备维护入口

设置首页保留四个分类大入口；“设备维护”放在固定底栏，不挤压原有卡片。
维护页解释范围，再次确认后才发送 `MSG_CMD_DISPLAY_RECOVER`。新增请求/结果
命令追加到共享表末尾，使用原有版本/序号预览 wire 格式，需更新双核应用。

小核使用控制层同一把锁检查：已确认的活动预览、STARTING/LIVE/STOPPING 的
RTSP、STARTING/RECORDING/STOPPING 的录像、活动或 poisoned 回放、媒体租约
owner mask。任一消费者仍占用就返回 EBUSY，清理失败保留的租约也不能绕过。

通过检查后保留占用，阻止新媒体启动；恢复请求与 ENTER/EXIT 共用一个待完成
事务，连接代次、序号、超时、发送失败和迟到结果沿用已有保护。大核仅在后端
就绪时尝试预览 EXIT，然后恢复图层；收到匹配的成功结果才清除预览和遗留
回放显示保护。失败、超时或断线不解除保护，不无限自动重试。

本地 UI 消息结果扩展为 int32，保留恢复错误码，不把所有 SDK 错误压成 -1。
消息 payload 保持自然对齐，并对状态结构对齐增加编译期检查；IPC wire 未变。

**这不是通用媒体资源重置。** 显示恢复不回收遗留 VENC/VDEC/ADEC/AO、媒体池，
不绕过 poisoned/租约保护，不重建摄像头或连接器，不自动开始任何媒体，也不
切网或重启设备。异常退出后的孤儿 codec 回收仍是待完成工作；恢复图层后
媒体若仍失败，需要串口重启业务程序并继续定位。
