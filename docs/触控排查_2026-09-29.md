## 已确定的问题和修改

1. main.c 没有调用 lv_port_indev_init；该函数自身也是禁用后的空函数。
   已恢复 Linux evdev -> LVGL pointer 注册，默认启用触摸，实体键保留备用。
2. 原读取循环读到 EAGAIN 才向 LVGL 返回，会把短按的 press/release 合并，
   LVGL 只看到 release。现改为每个 SYN_REPORT 返回一次，通过
   continue_reading 继续处理下一帧。
3. 非阻塞设置失败、设备读失败和注册失败现在会记录错误，避免静默失效。

未认定硬件误触已经修复，也未对新板做触控实测。

## 当前底层配置

- Linux：k230_canmv_lckfb.dts，I2C3，0x38，edt,edt-ft5306。
- INT：gpio23 的局部 offset 0，下降沿；不是 offset 23。
- RESET：port24 的局部 offset 0，低有效。
- 坐标范围：480x800；应用使用显示初始化提供的坐标映射。
- U-Boot：k230_canmv_lckfb.dts 中 IO23 已设置 IE=1、PU=1、PD=0。
  这是源码证据，不等于已测量板上电平或证明烧录的 U-Boot 包含它。
- Linux 驱动通过 input_mt_report_pointer_emulation 提供 ABS_X/Y 和 BTN_TOUCH，
  当前应用优先使用这一路，避免混用不同手指的 MT 坐标。

参考文章 https://blog.csdn.net/weixin_29184075/article/details/166163103
已读取。文章的 FT6236/GT911 和 GPIO14/15 是示例，不是本板原理图证据；
GPIO offset 应遵循实际控制器绑定，不能照抄全局编号或因此更换驱动。

## 不重烧系统的测试

Docker 已构建的 UI：
`/home/atlantis/k230_sdk/output/k230_canmv_lckfb_defconfig/little/buildroot-ext/target/app/lawrec/ui/ui`。
通过 Windows SCP 先传到板子 `/tmp/ui-touch`，不要直接覆盖运行中的程序。
小核执行（先确认没有脚本自动重启 UI）：

```sh
killall ui
sleep 3
pidof ui
```

确认 pidof 没有输出后：

```sh
cp /tmp/ui-touch /app/lawrec/ui/ui
chmod +x /app/lawrec/ui/ui
LAWREC_TOUCH_TRACE=1 /app/lawrec/ui/ui >/tmp/lawrec.log 2>&1 &
```

大核显示程序仍需按原方式运行；此次只更新小核 UI，不改摄像头显示链。
若误触影响操作，可停止 UI，使用 `LAWREC_TOUCH_ENABLE=0` 临时退回实体键。
Trace 只供短时诊断，日常启动不要开启，避免持续占用 /tmp。

将 tools/touch-diagnose.sh 推送到小核后执行：

```sh
sh /tmp/touch-diagnose.sh > /tmp/touch-diagnose.log 2>&1
```

执行期间连续点按10秒。另可使用 evtest（若系统提供），根据
`/proc/bus/input/devices` 中的真实触控设备选择 eventX，不硬编码 event0。

## 判定顺序

- 没有 input 设备：检查驱动 probe、供电、复位、I2C 错误。
- 有设备但触摸时 IRQ 不增长：检查 INT、电平、复用和实际 DTB。
- IRQ 增长但报 I2C 错误/无坐标：检查通信及触控 IC 协议。
- 原始事件正常但 UI 无反应：检查 touch enabled 日志及 LVGL 映射。
- 不碰屏幕也持续出现按下事件：优先验证原始事件、供电/排线和 INT，
  不用软件滤波掩盖硬件问题。
- 测试四角、中心、短点按、拖动、长按、多指、连续点击，核对 raw/mapped
  坐标是否一致；不在没有数据时随意加镜像或交换 XY。

已有的 SD 发布镜像未被覆盖；本次触控修改需要更新上述 UI 后才生效。
