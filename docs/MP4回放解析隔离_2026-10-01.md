# MP4 回放解析隔离

## 本轮实现

SDK MP4 库在读取容器、样本表和视频帧时存在 `assert`。仅检查文件头或关闭
断言不能解决越界、空指针和死循环。本轮保留 SDK，改为把回放所有 `kd_mp4_*`
解封装调用放到同一个 UI 可执行文件的无界面辅助子进程中。

```text
文件页 -> control -> playback worker
                       | 只读文件 fd + 私有 socketpair
                       v
                  同一可执行文件 --mp4-demux OWNER
                       | SDK 解析/取帧/销毁
                       v
                轨道信息、PTS、复制后的帧字节
                       |
                playback worker -> MAPI -> 大核 VDEC/ADEC/VO
```

仍然只有一个业务状态管理进程；解析辅助进程不启动 LVGL、DRM、IPCMSG、MAPI、
摄像头或编码器，不是恢复独立 service，也不是另一个播放器。录像 MP4 封装仍
由录像 worker 管理，本轮没有把录像 SDK 调用迁入辅助进程。

主要文件为 `little/src/playback/lawrec_demux.{h,cpp}`；回放 worker 在获取任何
媒体租约前读取轨道信息，之后按帧请求数据。父进程不接收子进程指针，版本化
私有协议检查命令、长度、错误码和 EOF；帧缓冲的有效期到下一次取帧为止。
现有格式范围仍为 H.264 1280x720、可选单声道 8 kHz G.711A/U，不增加格式能力。
补充检查第二轨首帧 PTS 与共同原点的差值，沿用 10 秒间隔上限，避免损坏元数据
溢出 chrono 等待时间。

## 所有权与异常行为

- 父进程先验证只读普通非空文件，再复制描述符。修复已关闭的输入编号被新建
  socket 复用的隐患；各个复制失败立即保存对应 errno。辅助进程再次验证输入。
- 使用 `posix_spawn` 而不是在多线程 UI 中 fork 后调用 SDK。输入固定为 fd3，
  私有 socket 为 fd4；辅助进程移除其它大于 4 的继承描述符，不保留媒体/显示句柄。
- 设置父进程死亡信号，并核对原始父 PID，覆盖被 subreaper 接管的启动竞态。
  清空继承的信号屏蔽，关闭 core dump，设置 no-new-privileges。
- 每次信息/取帧交换最长 8 秒，约每 50 ms 检查取消。空闲等待没有 8 秒限制，
  因此暂停不会因为解析器空闲而失败。每帧最大 4 MiB，子进程虚拟地址空间
  限 128 MiB；这些限制在长文件/板端内存布局上仍需实际验证。
- 解析崩溃通常表现为 `-EBADMSG`（-74），不支持的轨数为 `-ENOTSUP`（-95），
  超时为 `-ETIMEDOUT`（-110），用户取消为 `-ECANCELED`（-125）。
  worker 保持已有清理顺序，显示失败状态；正常停止也可能在正在取消解析时记录
  -125。`stop_wait` 成功表示 worker 已退出，不表示回放结果没有错误。
- 关闭 socket 后最多等待约 300 ms；未退出则 SIGKILL，再非阻塞等待约 300 ms。
  若子进程仍在不可中断的内核 I/O 中，保留唯一退休 PID，后续启动返回 -EBUSY，
  直到回收完成。不无限阻塞 UI，也不丢弃或覆盖未知子进程所有权。
- `[demux] start/operation/close` 日志包含 PID、结果、退出状态和是否强制回收，
  与 `[playback]` 的状态/媒体清理日志配合定位。

## 不能据此宣称完成的内容

这属于崩溃/阻塞隔离，不是安全沙箱：辅助进程仍具有原有 UID/权限，未用 seccomp
或隔离文件系统，不能承诺任意恶意 MP4 安全。已验证的样本不能覆盖所有 SDK
内存破坏路径，也不修复 SDK 本身。子进程资源限制不限制硬件解码器。

真实 SD 长录像的解析内存、启动耗时、帧传输吞吐、声音和播放效果均待板测。
SDK MAPI/硬件解码同步调用硬阻塞仍无法被应用取消，媒体清理失败仍需隔离资源
或重启。断电恢复、2h/8h 稳定性、触控与正常显示链验收不因本轮通过而完成。
