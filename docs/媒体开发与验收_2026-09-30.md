# 媒体开发版：RTSP / 录像 / 本地回放

## 实现边界

小核仍只有一个UI业务可执行文件，直接链接live555、MP4、MAPI。
大核保持摄像头、编码、解码、显示基础链；不启动demo、播放器进程或RTSP脚本。

- RTSP：预览成功ACK后，通过MAPI控制VENC0，跨核回调送live555。
  首帧后才进入LIVE，无帧8秒失败；端口8554、路径lawrec。
- 录像：同样要求预览ACK，VENC1回调写MP4，SPS/PPS/IDR齐全才进入RECORDING；
  写入临时文件，正常关闭并同步才发布`.mp4`，保留128MiB空间，不自动覆盖旧文件。
- 回放：从已完成文件列表选择Play；control拒绝与预览/RTSP/录像并发。
  只读描述符固定文件，SDK MP4解封装，小核按PTS毫秒节拍发送Annex-B到MAPI VDEC0。
  大核只切换视频图层：关闭camera layer1，配置layer0将1280x720缩放为480x270，
  显示位置(0,200)；Linux UI保留。退出后关闭layer0并恢复layer1。
  不重置connector、DSI或整个VO。

回放支持播放、暂停/继续、停止返回、EOF收尾、错误提示；仅单轨H.264 1280x720。
暂停停止送新帧，硬件里已排队的少量帧仍可能继续显示，不承诺逐帧冻结。
音频、多视频轨、任意分辨率、进度跳转和倍速不在本轮范围。

## 资源与已知限制

- 一条worker串行负责解封装、送流和释放。UI不直接销毁VDEC或VB。
- SDK `kd_mapi_vdec_send_stream()`忽略milli_sec并可能永久等待FIFO确认。
  应用停止等待超时会记录日志，不能强制回收在途块；需核对大核日志并恢复双核程序。
- 清理失败后保留media租约/未确认安全的池，禁止新媒体业务，避免悬空物理内存引用。
- SDK MP4 demux仍有assert，当前不对损坏/外部导入文件作安全承诺；
  只用本机正常完成的录像验收，解析器加固仍是后续待办。
- 运行时VB余量、VDEC输出池大小、VO layer0缩放与Linux DRM共存均需实板确认。
- 09-30 SSH检查数据分区256MiB，上传前剩余160MiB；大核ELF约16MiB，扣除保留量后
  仅能做短录像。长测前需要备份并扩容数据分区，不自动分区/格式化。

## 板端手动启动

大小核必须更新同一批程序；新命令使用现有door_lock IPC连接，不另占端口。
安装脚本只备份和替换停止状态的UI，不杀进程、不修改自启动。
执行安装脚本时必须传入本地UI和大核ELF的SHA256，校验不一致则拒绝安装。

续推修复：录像发布采用Linux renameat2(RENAME_NOREPLACE)，拒绝覆盖已存在的录像；
拒绝空文件、目录之外的临时文件和空参数。不支持该操作的文件系统会报错并保留.part，
不会退化成覆盖式rename。Docker测试覆盖目标冲突后旧文件内容不变；板端FAT发布仍待实测。

先在大核串口启动（不要同时运行旧fastboot_app）：

```sh
/sharefs/lawrec-media-20260930.elf /bin/retinaface.kmodel /bin/mbface.kmodel
```

确认`build media-playback-dev`和`preview backend ready`后，小核SSH启动：

```sh
/app/lawrec/ui/ui >/tmp/lawrec.log 2>&1 &
```

## 逐项验收

1. 进入拍摄，确认大核preview ACK和画面；单独启动RTSP，VLC使用TCP打开
   `rtsp://192.168.123.74:8554/lawrec`，停止后确认端口释放。
2. 停RTSP，再录像5秒后正常停止，确认/sharefs/lawrec_records生成非空.mp4，
   不是仅有.part。SCP导出，用ffprobe检查H.264、1280x720、时长和可解码性。
3. 返回主界面，文件页选择录像点Play，检查大核`[playback] display enabled=1 result=0`。
   小核必须出现PLAYING（state=2），只收到显示ACK不算解码成功。
4. 暂停/继续，Stop / Back回文件页，再进拍摄，确认摄像头能恢复且UI没有消失。
5. 分别重复启停，测试自然EOF、空目录、无存储和不支持格式；记录双核日志。
   硬阻塞、清理失败或SDK断言不是“测试通过”，停止压测先定位。

以上是待执行的验收步骤，不是实测结果。
