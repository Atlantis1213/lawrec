# UI 重启与显示状态同步

后续增量：已有二次确认的“设备维护 → 恢复显示”，不再只能通过重启处理
遗留显示图层；它不回收 codec/媒体池，不绕过清理失败租约。
详见 [显示恢复与设备维护](显示恢复与设备维护_2026-10-02.md)。下文描述本轮历史边界。

## 修复范围

UI 进程重启会丢失本地预览标记，但大核进程不一定重启。原实现把本地标记
初始值当作显示空闲，并且大核 IPC 线程在接收循环结束后没有重连路径。本轮
补齐重连生命周期和只读状态同步，不自动恢复录像、RTSP 或摄像头预览。

## 当前流程

1. 小核控制层启动时先保留显示占用，回放返回 EBUSY，不能凭本地零值放行。
2. IPC 首次连接或连接代次改变后，等本地 RTSP、录像和回放停止，再发送
   `MSG_CMD_DISPLAY_QUERY`。查询不初始化媒体、不修改图层。
3. 大核返回版本、序号、结果、后端就绪、预览 enabled/bound 和回放图层标记。
   预览字段在控制器锁内读取；这是软件占用快照，不是读取硬件寄存器。
4. 小核检查消息长度、版本、布尔范围、请求序号和连接代次。只有匹配的、后端
   就绪的结果才能收敛占用；发现残留预览不自动开启本地媒体。
5. 后端未就绪、查询失败或超时保持保护，最多约每 5 秒重新查询。用户主动
   ENTER/EXIT 会取消旧查询，迟到的空闲快照不能覆盖正在进入的预览。
6. 预览残留可通过进入拍摄再返回走正式 EXIT。大核遗留回放图层单独阻止回放，
   不能靠预览 EXIT 清除此标记；该分支目前需串口重启大核，尚未实现通用孤儿
   VDEC/ADEC/VENC 资源回收或在线显示恢复操作。

新增命令追加在共享命令表末尾，不改变既有命令编号和 ENTER/EXIT 协议。
状态体包含 7 个 32-bit 字段。旧大核没有查询命令，新 UI 会保持保护并记录
查询超时；升级应配套更新双核应用，不把单边升级当作已验收版本。

## 大核 IPC 与退出

`big/src/common/lawrec_ipc_server.{h,cpp}` 统一注册、try-connect、接收循环、重连、
发送与同步请求回包。发送固定当前句柄；断开先撤销句柄，再在锁外进行 SDK
清理，旧连接的同步回包不能发到新句柄。尚无对端时可停止，不再在业务线程中
使用阻塞 connect 等待。运行结束后重连，不重新初始化摄像头或显示。

main 只在成功创建线程后标记 started；失败和正常退出均先停止/join 已启动的
业务线程，再拆卸相关媒体后端。服务注册结果不再丢失，线程创建错误有日志；
部分原先直接提前返回的 deinit 错误仍会继续公共清理，保存首次错误并返回失败。
大核 SDK 的 connect/run/disconnect 真实行为及异常终止仍需板端验证。
