# 共享编码接入与验收

## 当前路径

大核 VI1 -> VENC0 H.264 1280x720 -> MAPI 回调 -> 一次复制的不可变帧 -> 两个独立有界队列。
RTSP worker 向 live555 送帧，录像 worker 封装 MP4；两路不在 SDK 回调中执行网络或磁盘操作。
首次订阅初始化编码器，后续订阅请求 IDR 并等待 SPS/PPS 齐备；最后退订才释放硬件。
媒体租约允许 owner1/2 共存，owner3 回放仍互斥。显示链不随退订关闭。

## 失败边界

- 单路队列溢出只让该消费者失败，不停止另一消费者。
- 清理失败将编码管理器隔离，拒绝重新启动，保留媒体租约并要求重启。
- UI 返回等待两路停完，再发送预览退出；返回等待期间不接受再次启动。
- 音频仍未接入，本轮并发只针对视频。SDK 同步调用硬阻塞问题尚未解决。

## 最小实板验收

1. RTSP 先开、录像后开，然后单独停 RTSP，检查录像继续且文件可解码。
2. 录像先开、RTSP 后开，然后单独停录像，检查 VLC 继续且录像正常发布。
3. 两路运行时返回，检查两路结束、8554 释放和预览退出，不关闭底层显示链。
4. 录像分段时继续拉流，检查新段首帧可解码、RTSP 不断流。

日志应只有首次订阅初始化 VENC，订阅 mask 为 2/4/6，最后退订 mask=0。
Docker mock 只能验证所有权、失败隔离和软件顺序，不能替代上述硬件验收。
