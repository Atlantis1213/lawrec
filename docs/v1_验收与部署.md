# v1 开发候选包与板端验收

更新日期：2026-10-02。本文描述当前源码和新生成应用包，不是 09-29 旧候选包的
功能声明。软件目标为单业务进程、预览、RTSP/录像并发、可选音频、分段、文件
浏览/导出、本地回放、网络与参数设置。已有实现与软件验证不等于实板验收。
正式 v1.0.0 仍须通过《持续开发验收清单》的全部门槛。

## 架构和边界

- 小核仅运行 `/app/lawrec/ui/ui`，control、media、RTSP、record 在同一进程内。
- 不运行旧 lawrec_service、lawrec_rtsp 或 RTSP 启停脚本。
- 大核负责采集、显示和编码；小核通过 MAPI 控制编码并接收码流。
- 显示链持续运行，预览只控制摄像头视频图层。
- 固定 H.264 1280x720，15/30 目标 FPS；RTSP/录像共享 VENC0 和 G.711A 音频
  订阅，可分别启动/停止。音频默认关闭，真实并发、帧率及声音待板测。
- 预览协议增加版本和请求序号，必须同时更新两核程序。
- 文件页每页四条双向浏览、详情、冻结目标的删除确认及 SCP 导出说明。
- 本地回放支持 H.264 720P 与可选 G.711A/U 单声道 8 kHz 音轨；暂停/继续/退出。
  回放独占媒体，与预览/RTSP/录像互斥；跳转、倍速和 AI 扩展不在本轮范围。
- 设置按视频、网络、存储、时间分类。媒体/目录保存后重启 UI 生效；保存网络
  与在线应用是独立动作，后者必须确认且可能断开 SSH。
- 触控依赖已通过的 ST7701 面板序列、27 MHz/324 Mbps/4 lane、正常 VO/VTTH。
  应用包不含内核，不能用替换 ELF 的方式修复旧内核中的面板初始化。

## 构建与产物

干净且已审查提交使用 `bash tools/package.sh`，Docker 完整软件测试及双核编译后
生成 `out/releases/v1.0.0-rc1-<revision>-<UTC>.tar.gz`，仍不是硬件已验收的正式版。
工作区未提交时使用 `bash tools/package.sh --snapshot`，生成明确标记的
`lawrec-dev-<UTC>-<base-revision>.tar.gz`；只跑定向包完整性检查和双核 Docker
构建，不伪称又跑过全部功能测试，不自动提交、推送或部署。

包内包括双核程序、两份 LVGL/输入库、S99lawrec/S45wifi、部署/验收文档、源码
快照及内容/权限清单、选定的 SDK 显示/触控适配源文件、测试/构建日志。
`BUILD.txt` 记录基础提交、快照摘要、SDK 状态、Docker ID 和实际测试范围；
`SHA256SUMS` 与 `verify.sh` 核对内容、关键执行权限、缺失/额外文件和符号链接。
构建期间源码或选定 SDK 输入改变则拒绝发布，并验证实际解压后的包及源码。
校验只提供完整性，不是签名、恶意包安全沙箱或硬件兼容性证明。

Docker ELF 检查拒绝非 RISC-V/ELF64/小端/LP64D 或错误文件类型，检查结果随包保存。
大核 `.got` 的历史 SDK 节表类型/entry-size 告警被精确识别并记录，其它 ELF
诊断不放行。相同告警也在先前触控镜像中存在；不为消除工具告警改动链接布局，
仍要求当前应用实板加载和运行验收，见 [离线开发包与构建追溯](离线开发包与构建追溯_2026-10-02.md)。

当前 SDK 不在 Git 仓库内，明确记为 `unavailable-unversioned-sdk`。选定文件的
哈希不代表完整 SDK 已归档；恢复构建仍需完整 SDK、工具链和同一 Docker。
应用包不是 SD 镜像，不替换 RT-Smart/Linux 内核，不包含模型或真实 WiFi 密码。
09-29 旧包及 10-01 旧 SD 镜像不会自动获得当前业务、映射、网络和设置增量。

## 更新板子

通过 Windows PowerShell 的 scp 将包传到已确认 IP 的板子 `/tmp/`。
WSL 文件来源为 `\\wsl$\Ubuntu\home\atlantis\lawrec\out\releases\`。

1. 先完成录像收尾，再在小核停止 UI：`/etc/init.d/S99lawrec stop`。若停止超时，
   不覆盖程序/库、不用 kill -9 强制收尾，先查看日志。安装前确认大核程序已退出。
2. 确认旧 `lawrec_service` 和 `lawrec_rtsp` 没有运行，避免争抢媒体和端口。
3. 从已核对来源解压包，在包目录执行 `sh verify.sh`，并核对 BUILD.txt 的板型与
   内核前提。不确定当前内核是否含修复时，先记录/核对固件，不盲目更新应用。
4. 停止大核旧程序后将 `lawrec.elf` 传至 `/sharefs/lawrec.elf`；不能覆盖正在运行的 ELF。
5. 小核安装包内 `app/lawrec/ui` 到 `/app/lawrec/ui`，`lib` 下库到 `/usr/lib`，
   `etc/init.d/S99lawrec` 和 `etc/init.d/S45wifi` 到同名位置。S45wifi 必须与 UI 配套；
   不在唯一 SSH 通道上在线重启网络脚本。必要时按实际根文件系统重新挂载可写。
6. 保留旧程序/库/脚本作为回退，核对安装文件哈希，设置程序和两份脚本为可执行。
7. 大核串口手动运行 `/sharefs/lawrec.elf /bin/retinaface.kmodel /bin/mbface.kmodel`。
8. 小核手动运行 `/app/lawrec/ui/ui`。日志为 `/tmp/lawrec.log`。

若大核异常退出后资源不能恢复，重启后再手动启动。不要重复启动多个大核程序。
开机自启仍由 `/etc/lawrec-ui.autostart` 文件决定，更新包不会自动创建它。

权限设置命令（安装后手动执行，不会启动程序）：

```sh
chmod 755 /app/lawrec/ui/ui /etc/init.d/S99lawrec /etc/init.d/S45wifi /sharefs/lawrec.elf
```

## 存储准备

先通过 `mount`、`df -h` 确认实际 SD 持久化分区和剩余容量，不自动格式化。
在已确认的持久化分区创建录像目录，把绝对路径写入 `/etc/lawrec-record-dir`，重启 UI 生效。
默认目录 `/sharefs/lawrec_records` 不会自动创建，也不意味着已确认其挂载正确。
调试可用 `LAWREC_RECORD_DIR=/实际目录 /app/lawrec/ui/ui` 覆盖。

后续开发增量新增 Settings -> Storage 路径编辑、Check 和二次确认 Save，
仍沿用上面的文件格式，保存后重启 UI 生效。路径最多 80 字节，只接受规范绝对
ASCII 路径（字母/数字/._-/），拒绝符号链接、点路径分量和错误配置；错误配置
不会静默写入默认目录。旧候选包不包含这个页面，构建和板测边界见
[录像目录设置](录像目录设置_2026-10-01.md)。

程序拒绝 tmpfs/ramfs、只读或缺失目录；预留 128 MiB，不循环删除旧录像。
正常结束才将 `.part` 发布为 `.mp4`；异常留下的 `.part` 不表示可恢复。
文件页按名称游标分页，不再受旧 100/1000 条静默截断限制；只显示非空普通的
已完成 `lawrec_*.mp4`，不跟随符号链接。导出用 SCP，`.part` 不进入删除列表。
删除确认后重新比较设备/inode/大小/mtime；这不是对外部并发换名的原子保护。
显示的写入量为编码数据字节数，最终文件大小以文件页为准。

## 已知限制

- SDK 同步 MAPI 调用或文件系统 I/O 可能阻塞，应用超时无法取消内核/SDK 内部调用。
- 媒体回收接口失败后保留占用，避免复用未确认释放的资源。回放分别报告播放/
  清理原因，停止等待及退出 owner mask 如实反馈；单独重启 UI 不证明大核硬件
  已回收，无法确认时按串口完整重启方案验收。
- MP4 没有断电恢复保证；删除与普通文件发布的同步不等于断电保护。
- DHCP hook 返回失败尚未驱动 BusyBox 发送 DHCPDECLINE/恢复；未分段长录索引
  仍可增长，自动停止策略尚待确认。不能因此声称网络和长测门槛已完成。
- 码流队列有上限；H.264 输出拥塞后等待下一个 IDR，原始队列溢出终止会话。
- 显示维护不能回收孤儿 VENC/VDEC/ADEC/AO/VB；清理失败需按串口恢复方案重启。
- 真实 VI/VENC、声音、MP4/回放和长测尚未验收，不能据此发布正式 v1.0.0。
