# 录像分段音频同步与 MP4 时长

## 修复的缺口

上一增量解决停止时直接清空音频队列的问题，但仍把完整包写入一段，也没有
在 IDR 关闭旧文件前等待迟到音频。SDK 的 STTS 时间表把最后样本固定成 1 ms，
轨道时长另用平均帧距估计，单样本可能为零；音频有首包延迟时，轨道/影片时长
又没有正确包含这段延迟。只修队列无法保证最终文件的时间信息正确。

本轮完善 M2/S06、M3/A04 的软件实现，不改变显示/触控参数、音频默认关闭、
共享 VENC/AI/AENC 和单 Linux 业务进程的边界。

## 录像写入顺序

1. worker 直接消费共享编码器交付的不可变帧，解析 SPS/PPS/IDR，不再拼造 SDK
   回调结构并再次复制整帧。只有新段缺少编码头时才分配合并缓冲。
2. 首个有效 IDR 写入后确定段原点。音频在这之前不被提前丢弃；首包跨过原点
   时按样本起点裁剪，而不是扔掉整包。
3. 平时只写结束 PTS 不晚于已处理视频边界的完整音频包，避免每个视频帧都
   把同一音频包拆成过短的 MP4 样本。
4. 到达分段 IDR 后，旧段等待音频覆盖该 IDR 的 PTS，队列等待预算约 250 ms。
   不持录像状态锁等待。到达边界后设置末帧时长、关闭并发布旧段，再打开新段。
5. 音频游标包含共享帧和已消费字节数。G.711A 单声道 8 kHz 按 125 us/字节
   分配：切点前的样本起点属于旧段，其余留给新段；包内切点误差不足 125 us，
   不复制包、不丢余部、不重复样本，也不把捕获 PTS 改成消费时刻。
6. 正常停止用最后接受视频 PTS 加一个名义帧周期作为边界，按同一游标裁剪尾部。
   一帧经过校验并开始音频处理后属于“在途帧”：停止请求到达时完成该帧，随后
   不再接收下一帧，避免音频已写到一个最终没写入的视频边界。

队列错误、缺少边界数据、迟到超时、非法长度/PTS、写入、时长设置、关闭等错误
都阻止当前段发布，保留 `.part` 和首次错误。已经成功发布的旧段保留。音频源
PTS 必须严格递增；不靠重写时间戳掩盖缺失数据。日志区分 `phase=segment/stop`，
记录段号、边界、实际音频结束 PTS、包数、错误码。

## MP4 时长适配

继续使用项目内 `record/prepare_mp4.cmake`，只在构建输出生成适配，不改 SDK
原文件。本轮受指纹约束的四份输入为 `mp4_format.c`、`mov-writer.c`、
`mov-stts.c`、`mov-elst.c`；指纹不同直接拒绝构建，升级 SDK 必须重新审查。

writer 利用已预留的额外样本槽记录末样本的独占结束 PTS，不写伪造媒体样本。
音频默认末时长按字节数/声道/采样率计算；录像 worker 在 IDR/停止前通过
`lawrec_mp4_muxer_end_track()` 明确设置视频与音频结束点。STTS 与 mdhd 使用
一致的媒体时长，tkhd/mvhd 包含首包延迟，edit-list 的可播放部分仅包含媒体时长。
输入 DTS 倒序或重复明确失败，不让 STTS 断言在封装关闭时才出现。

封装仍用选用 SDK 的 1000 Hz 时间基：帧 PTS 向下换算到毫秒，最终结束点向上
换算到毫秒；容器有不足 1 ms 的量化，不能宣称亚毫秒 MP4/硬件同步。样本分配
仍假定 AI/AENC PTS 指向首样本，需板测确认；15/30 FPS 也是目标配置，而非
实测结果。暂停/停止音频输出、短包 ADEC 接受能力及 AI/VENC 时钟同源仍待板测。

## 已执行的精简验证

```bash
bash tools/test.sh record-io
bash tools/test.sh playback
bash tools/build.sh little
```

Docker 定向检查覆盖段首裁剪、迟到 IDR 音频、包内切点、两段字节拼接连续、
停止期间在途帧完成、下一帧拒绝、缺数据/超时/溢出/非法 PTS/元数据失败。
真实 SDK 写入并读回 160/320/80 字节音频包；直接检查 STTS、mdhd、tkhd 和
edit-list，同时验证单帧视频与单字节音频尾包的时长、字节和 PTS。保留原写盘
故障、fast-start 和资源回收测试；回放 mock 增加 1/319 字节短包路径。

四份生成文件在 native 测试与目标构建中 SHA256 完全一致；Docker readelf 确认
目标包含末轨道时长 API 与适配的时间表/编辑列表符号。编译没有新增 C/C++
警告，CMake 仍提示 Buildroot 传入的若干未使用 `BUILD_*` 变量。
证据：`out/record-sync-tests.log`、`out/record-sync-playback-tests.log`、
`out/record-sync-build.log`。未上板、未重启/切网、未生成 SD 镜像。

后续必须实板检验段首可解码、音频短包、拍手/闪光同步、并发停止以及持续录制，
软件结果不能替代这些验收；SDK stop 与文件系统调用也没有硬超时保证。
