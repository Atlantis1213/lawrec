# IPv4 在线应用

## 使用语义

WiFi -> IPv4 中 Save 保存下次启动草稿；新增 Apply Now 只应用页面当前设置到
当前 wlan0，不保存草稿、不切换 SSID。两者各自二次确认，混用按钮不算确认。
Apply Now 可能中断 SSH 和 RTSP，先准备串口。成功后若需要重启保留，再单独 Save。
本轮未部署或执行板端切网，触控面板诊断镜像和测试 ELF 完全保持不变。

## 事务与恢复

1. 后台串行请求复制页面设置，校验参数；持有与启动应用共享的 flock，拒绝忙碌、
   外部 DHCP/启动 worker、非 COMPLETED 关联和已存在不确定状态。静态候选地址
   先完成 ARP 检查，冲突在停 DHCP/写标记之前结束，旧策略不变。
2. 读取当前已生效策略作备份，先原子写 incomplete 标记，再等待自有 DHCP 退出。
3. 应用新静态配置或获取持续 DHCP 租约。静态核对实际地址/掩码及关联状态，DHCP
   核对有效客户端/hook/当前地址。命令和 resolver 更新成功后提交运行态并清除标记。
4. 应用失败、取消、异常或提交失败，先停止可能残留的新 DHCP，再忽略取消但保留
   操作超时地恢复旧策略；恢复验证成功后重新提交旧运行态。原请求仍报告失败。
5. 恢复失败显示独立 rollback_error，保留 incomplete；后续在线改网拒绝执行，
   避免把部分配置当作 DHCP 成功。正常退出 UI 会等待后台事务及恢复完成。

事务抽象 `lawrec_ipv4_transaction.cpp` 只编排步骤，实际命令、租约和状态读取仍在
`lawrec_network.cpp`。UI 主线程轮询结果，不由 worker 操作 LVGL。
回到页面时若结果已被更新请求替代，提示查看状态，不误报旧 Apply 已成功。

## 边界与板测

本地配置成功不等于远端可达；目前没有连通性确认倒计时或网关/DNS 探测。
ARP 增量见 [IPv4 地址冲突检测](IPv4地址冲突检测_2026-10-01.md)，无冲突不是
永久空闲/可达保证。地址/网关合法但不可达时不自动回退。DHCP 恢复是重新获取租约，不保证
回到原 IP。恢复保存的旧策略，而非任意管理员手动添加的 wlan0 多地址/路由快照。
没有断电/强杀事务恢复保证；不确定标记用于拒绝假成功，不是自动修复证明。

触控诊断结束并恢复完整业务链后，在串口保底下用路由器预留地址验证：
DHCP -> 静态 -> DHCP 的实际地址/路由/DNS；Apply 不改草稿，Save 不改当前连接；
DHCP 无回应或配置命令失败时旧策略恢复，恢复失败时标记和错误可见；重启后用
保存草稿，而非未保存在线策略。核对 eth0 的路由和 DNS 未被删除。
日志 `/tmp/lawrec-ui.log`、`/tmp/lawrec-ipv4.log`、`/tmp/lawrec-dhcp.log` 及自有
DHCP job/events.log。出现不确定状态先用串口检查原因，修正下次启动草稿并重启；
不要仅删除 incomplete 来伪装成功，也不要在唯一 SSH 通道无串口保障时切换。
