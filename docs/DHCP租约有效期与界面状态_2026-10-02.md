# DHCP 租约有效期与界面状态

## 修复的问题

过去只检查 udhcpc 是否存活，以及 lease 文件的 error/秒数/IP。文件没有时间
基准，因此进程仍活着但长期未成功续租时，旧记录可能无限期显示 bound；UI
也没有使用已有 DHCP 错误字段，容易把“网卡还有地址”误认为租约仍有效。

本次补只读状态判定和提示，不重写 DHCP 协议、不自动切网，也没有新增守护进程。

## 当前实现

lease 使用以下 v2 格式，原子写入同一 job 的文件：

```text
v2 <error> <lease_seconds> <IP或-> <hook_received_boottime_ms> <boot_uuid>
```

时间来自 `CLOCK_BOOTTIME`，与 UTC 校时无关，包含系统挂起时间；启动 UUID 来自
`/proc/sys/kernel/random/boot_id`。成功要求 error=0、正租期和可接受 IPv4；失败
要求负 errno、租期=0、地址为 `-`。数字、范围、字段数和 UUID 均严格校验。

bound/renew 在业务 hook 入口冻结时间，成功后沿用这一时间，不在 DNS/地址
配置完成时重新开始计时。若租期在 hook 内已过，写入 ETIMEDOUT，不发布成功。
注意：这是**应用收到 hook 的本地时刻，不是 DHCPACK 的精确接收时间**；当前
BusyBox 会先执行内置 ARP 检查，因此不能宣称与服务端到期边界完全相同。

读取时固定 pidfd 并核对 job/客户端参数；读完元数据后重新检查 job 是否仍是
current、客户端是否仍活着。拒绝跨启动记录、未来时间和格式异常；到期返回
未 bound、ETIMEDOUT、剩余=0。未到期的剩余时间向上取整到秒。
观察器不删除地址、发送 DHCP 报文或拉起客户端；实际 deconfig/重获仍归客户端。

## 界面与观察频率

- `lawrec_network_get()` 最多每秒查询一次自有 DHCP job，锁外读取、锁内更新；
  若业务已开始或快照 generation 改变，不覆盖新结果。异常变成明确错误。
- 租约状态变化有 `phase=dhcp-observe` 日志；剩余秒数递减不逐秒刷日志。
- 网络页进入时异步读取 STATUS，页面可见且无弹窗/进行中业务时约每 5 秒刷新；
  不自动扫描、连接热点、获取 IP 或应用配置。
- `scan_generation` 与一般快照 generation 分开，租约变化不会重放旧扫描结果。
- 连接状态、租约提示、热点操作提示分开；有效租约青色、异常橙色，扫描或填入
  SSID 不覆盖过期提示。保存与在线操作仍各自确认，不改变当前网络的保存语义。

## 格式升级与未完成项

旧三字段 lease 没有时间基准，按 EPROTO 处理，不根据文件 mtime 猜租期。
升级后下次成功 hook 会写 v2；需要立即重新获取时，须串口保底、确认后使用
“重新获取 IP”。旧客户端已经存活也不能让旧记录变成可信。降级也应停止自有
DHCP job 后再重建；不要靠只重启 UI 转换租约格式。

已核对当前 SDK BusyBox 1.33.0：`udhcp_run_script()` 丢弃 `spawn_and_wait()` 的
返回值，ACK 路径在 hook 失败后仍可能进入 BOUND。因此当前 hook 拒绝不是
DHCPDECLINE/自动恢复证明。内置 `-a2000` 的冲突检查保留，但其 I/O 错误仍不能
等同于地址空闲；应用再次检查、拒绝配置，也不能替代客户端状态机适配。
SDK 输入 `networking/udhcp/dhcpc.c` SHA256：
`d94bdfa8564f4f24705d7359dd69e87dde6ac4630cb9b7a49ffbdd9ec32f2068`。

增加项目专用 udhcpc、保留系统 `/sbin/udhcpc` 的方案已询问，尚未获得确认，
本轮未引入或替换客户端。完整冲突恢复、真实 DHCPDECLINE/T1/T2、到期撤销/
重获、挂起恢复、外部修改地址、AP 断链与板端网页/SSH 可达性仍待实现或验收。
不能据此宣布网络功能全部交付，整个工程目标仍在进行中。
