# 录像分段开发版

## 实现

- 仍由大核 VENC 编码，小核 MP4 写盘，不重启摄像头、编码器或显示链。
- Session 状态保留总时长/字节数，Segment 状态单独维护首 PTS、已写帧数和文件句柄。
- 缓存最新 SPS/PPS，各不超过 32 KiB；参数单独到达时不写入无图像的 MP4 sample。
- 达到配置时长后 worker 在锁外调用 MAPI request_idr；等待超过 5 秒则失败停止。
  SDK 同步调用自身若阻塞，应用仍不能保证此调用可取消，这是已有 SDK 边界。
- 回调遇到满足时长的 IDR 才关闭旧 muxer。关闭、文件同步和发布成功后创建下一段，
  当前 IDR 只写入新段，补入缺少的 SPS/PPS，PTS 从零开始；会话单调时长不归零。
- 关闭/发布/空间检查/新文件创建或写入失败停止录制；已发布片段保留，失败段保持 .part。
- 写盘和分段已经移入录像 worker，共享编码回调只复制码流并入队。
  录像队列限制 64 帧/8 MiB，溢出明确失败停止，不默默丢帧；正常停止边界为当前正在写的帧，
  排队尾帧丢弃。切段 fsync 仍可能造成积压，不能据模拟测试宣称慢卡并发稳定。

## 软件验证

- Docker 命令：`bash tools/test.sh`、`bash tools/build.sh little`。
- 日志：`out/segment-tests.log`、`out/segment-build.log`。
- `tests/record_segment_test.cpp` 直接调用生产录像回调，mock MP4/存储 API，覆盖：
  SPS/PPS 独立到达、首 IDR 门槛、非关键帧跨时长、关键帧单次分配、段首 PTS=0、
  编码参数保留、后续空间不足、关闭失败、写入失败、PTS 回退和停止后的回调拒绝。
- 配置测试覆盖分段值持久化、旧配置默认关闭、非法范围及修改端口保留分段值。
- mock 没有运行硬件编码器/真正 MP4 库，不证明实板每段能播放或真实时间戳连续。

## 尚需验收

1. 实板选择 60 秒，录制至少 3 段；导出所有 MP4，用 ffprobe/解码器检查段首和时间戳。
2. 核对输入帧序号和各段总样本数，不重复、不漏分段边界帧。
3. 验证申请 IDR 失败/长时间无 IDR、慢 SD 卡、分段时返回页面、空间不足时提示。
4. 进行一小时分段长录、异常结束及断电试验。最后 .part 不承诺断电可恢复。
5. 音频开发后补音视频共同时间基准及分段同步；当前只覆盖纯视频。
