# 媒体失败隔离与设置反馈

本轮继续收尾 M1 媒体生命周期与 M4 设置体验，仅修改小核业务、页面及定向
验证入口。没有修改大核、Linux 触控、显示时钟、PHY 或面板命令序列。

## 媒体修复

| 问题 | 当前处理 |
| --- | --- |
| AENC 致命回调失败后，旧订阅者未退出，新订阅者仍可加入 | 保留源错误；旧所有者全部退出前拒绝加入，不自动重启硬件 |
| VENC/AENC start 返回成功，但启动期间回调已报错 | 在接受订阅前用回调锁检查源错误，失败时解除本次投递并清理首次启动资源 |
| 多个 SDK 清理调用连续失败，后一个覆盖首个错误 | 继续尝试全部清理并记录各自原始错误，接口保留第一个标准化错误 |
| 清理失败后，后续调用只返回泛化 EIO | 进程内隔离保留首次错误；拒绝新订阅，重复注销可查询同一错误 |
| SDK 正数错误被误当作业务成功 | 返回负数错误；非 errno 正数标准化为 EIO，日志保留 SDK 原值 |
| RTSP 音频与视频清理同时失败 | 保留首次清理错误，不改变既有媒体租约保留逻辑 |

SDK stop/unregister 始终在回调锁外执行，避免 SDK 等待回调时死锁。队列慢
消费者仍只影响自身，不把队列溢出误当成共享源失败。启动检查之后发生的
异步错误仍由队列报告；订阅被接受不等于已经收到有效帧。

隔离不是硬件回收成功，未增加自动复位/恢复策略，也未改变当前并发规则。

## 设置体验

- 网络页压缩正常连接摘要，保留 SSID、IP 和租约状态，删掉重复说明。
- 热点名称和密码增加永久字段标签；输入后名称不会消失，空字段显示示例/长度提示。
- 保存与校验反馈放入按需显示的独立结果卡，不再被被动连接刷新覆盖。
- 在线连接/重新获取 IP 的进度仍放在连接状态区域，完成后由后台结果更新。
- 码率名称、单位和范围放在数值上方；保留固定底栏、按需键盘和二次确认。
