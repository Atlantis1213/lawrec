# 触控 VO_CONFIG_ONLY 分段测试

## 变化与目的

上一轮用户反馈：完整 VO 输出、VTTH 请求关闭后仍迟钝、鬼触。本轮只跳过
`st7701_vo_resolution_init()` 最后的 `connector_set_vo_enable()`：

```c
connector_set_vo_init();
connector_set_vtth_intr(0, intr_line);
connector_set_vo_param(&attr);
// connector_set_vo_enable();
rt_kprintf("[touch-test] VO_CONFIG_ONLY: skip connector_set_vo_enable\n");
```

`st7701_init()` 仍调用 VO helper；时钟、PHY、DSI/面板命令、参数均不改，
应用复用同一个 connector-only ELF。共用 ST7701 helper 的其它屏型也受影响，
仅用于当前 480x800 板定位，不用于正常 UI/摄像头/RTSP/录像业务。

本地 SDK 库反汇编确认 `vo_init()` 内部调用 `kd_vo_set_vtth_intr(1, 10)`，
外层随后才请求关闭。此轮同样不是“整个过程中完全没有 VTTH”的对照实验，
也没有硬件状态读回。跳过 enable 不会清除上轮硬件状态，必须完整断电上电。

## 用户反馈

用户确认本组触控正常，加入最后的 `connector_set_vo_enable()` 才复现。
当前本地 SDK 库的 Docker 反汇编确认：`kd_vo_enable()` 写入寄存器后调用
`kd_vo_timestamp_enable()`。下一轮只增加时间戳调用，继续跳过 VO enable，见
[时间戳分段测试](触控TIMESTAMP分段测试_2026-10-01.md)。目前不能直接认定
是持续 MIPI 传输干扰，须区分附带时间戳操作及配置提交生效后的状态。

## 操作步骤

1. Windows 打开下列目录，用 balenaEtcher 烧录 `.img`。整卡烧录覆盖 SD 数据，
   需要保留的录像和配置先导出。

   ```text
   \\wsl$\Ubuntu\home\atlantis\lawrec\out\touch-vo-config\20261001T074303Z\artifacts
   ```

2. 完整断电再上电，不启动 UI。重刷后重新传入同一测试程序（IP 用当前地址）：

   ```powershell
   scp "\\wsl$\Ubuntu\home\atlantis\lawrec\out\touch-vo-config\20261001T074303Z\artifacts\lawrec-touch-clock-phy.elf" root@192.168.123.74:/sharefs/lawrec-touch-clock-phy.elf
   ```

3. 小核先启动 evtest，松手观察初始状态：

   ```sh
   chmod +x /sharefs/lawrec-touch-clock-phy.elf
   evtest /dev/input/event0
   ```

4. 大核串口执行：

   ```sh
   /sharefs/lawrec-touch-clock-phy.elf
   ```

   必须看到新驱动标记；应用旧 CLOCK_PHY_ONLY 名称不代表本轮阶段：

   ```text
   [touch-test] VO_CONFIG_ONLY: skip connector_set_vo_enable
   ```

5. 先松手 10 秒，再点击中央和四角，再松手观察释放。记录无人触碰时是否
   持续上报、实际点击是否迟钝、DOWN/UP 是否完整、大核初始化返回值。
   屏幕黑着是允许的，不以显示是否正常作为触控结论。测试 ELF 等待 60 秒
   后退出，但硬件不会恢复；下一轮必须冷启动。

## 结果判断

| 结果 | 下一步 |
| --- | --- |
| 触控正常 | 最终 VO enable 调用或其使配置生效后的状态是关键触发条件；查扫描输出、持续 DSI 传输和附带操作 |
| 仍迟钝、鬼触 | 触发发生更早；继续拆分 connector_set_vo_init 与 connector_set_vo_param，不排除 init 内短暂开启 VTTH |
| 缺少新标记或初始化失败 | 先核对烧录固件及执行过程，不能作分段判断 |

`sysrq: HELP` 是 Linux SysRq 帮助，不是触控驱动报错或系统崩溃证据；可由
串口 BREAK 后字符、快捷键或软件触发，保留原日志，不据此更改本轮变量。
