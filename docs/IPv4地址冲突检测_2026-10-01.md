# IPv4 地址冲突检测

## 实现与接入

新增 `little/src/common/lawrec_arp.{h,cpp}`。直接使用绑定 wlan0 的 Linux
AF_PACKET/SOCK_DGRAM socket 收发 ARP，不调用 shell/arping，不修改 IP、路由或
DNS。Probe 使用以太网/IPv4 请求、自己的 SHA、零 SPA/THA、候选地址 TPA。
识别其它有效单播 MAC 对候选地址的声明（请求或应答 SPA），以及同时探测
同一地址的请求（SPA=0、TPA=候选地址）。忽略自己的反射、发出方向、其它网卡、
无关地址和不合法/截短报文，不用非对齐整数指针读取网络数据。

发送三次 Probe：初始随机等待 0-1 秒，两次间隔各 1-2 秒，最后再观察 2 秒。
正常检查约 4-7 秒；循环有 9 秒单调时钟截止，每次 poll 最多 50 ms 检查取消。
开始、每次发送及完成时核对网卡 UP/RUNNING、索引和 MAC。随机数使用非阻塞
getrandom；无法获取、无 CAP_NET_RAW、socket/bind/send/recv 失败、接口变化均
明确返回错误，绝不当作“地址可用”。截止不是所有内核 ioctl 的硬取消保证。

| 路径 | 行为 |
| --- | --- |
| IPv4 Apply Now 到静态 | 事务 preflight 中检查，在 incomplete 标记和停 DHCP 之前；冲突直接结束，changed=0，旧 DHCP/IP/路由/DNS 不变 |
| 成功 preflight 后在线配置 | 复用本事务刚检查的候选地址，不重复等待；应用失败仍走原回滚 |
| 启动静态、换热点静态及静态回滚 | 在修改 IP/routes/DNS 前检查；失败拒绝继续，回滚失败保留独立错误/不确定状态 |
| DHCP 首次 bound 或地址/掩码变化 | hook 独立检查候选地址，通过后才配置并记录 bound；相同地址/掩码 renew 不重复完整检查 |
| udhcpc 获取/续租 | 增加 BusyBox 附着参数 `-a2000`，明确的冲突应答由客户端发送 DHCPDECLINE；保留持续后台运行，首次获取外层等待从 20 增至 30 秒 |

BusyBox 原 ARP 函数部分传输失败会返回“无应答”，所以不能只打开 -a。
本工程的 hook 再检查是为了拒绝无法完成探测的租约，而不是重写 DHCP。
如果只有工程 hook 检出同时 Probe 或传输失败，BusyBox 不会仅因 hook 非零自动
发送 DHCPDECLINE；本地拒绝标记 bound，首次获取报告失败并尝试回收客户端，
后台续租记录失败但不承诺自动重新选址。这一边界仍需实板验证和后续完善。

`[arp] probe/result` 日志包含候选地址、次数、耗时、错误及冲突 MAC。
`-EADDRINUSE`（-98）表示检测到冲突；`-EPERM`（-1）、`-ENETDOWN`（-100）、
`-ESTALE`（-116）、`-ECANCELED`（-125）分别区分权限、链路、接口变化和取消。
IPv4 页面将 -98 显示为 IPv4 address conflict，区分“未开始变更”和“已回滚”。

## 边界与板端验收

ARP 未检测到冲突仅说明本次窗口没有收到符合条件的报文，不证明地址永远空闲。
离线设备、AP 客户端隔离/代理 ARP、丢包及探测完成后的竞争均可能影响结果。
不是完整 RFC 5227 状态机：尚无运行期防御/持续监测、完整公告和冲突计数策略；
不是网关/DNS可达性检查，也不自动换一个静态地址。DHCP 后台 hook 阻塞时，原有
3 秒 stop 等待可能超时并保留客户端元数据，不强杀或谎报回收完成。

触控诊断结束且串口可恢复后，使用可控热点验证：

1. 用另一台设备占用候选静态 IP，Apply Now 应报 -98、changed=0，旧连接/租约保持；
   换空闲地址应完成检查，再观察实际 IP/掩码/路由/DNS。
2. 静态启动/换网时遇冲突不报告成功；回滚旧静态地址也遇冲突时显示不确定状态。
3. 可控 DHCP 服务器给出占用地址，捕获 DHCPDECLINE、重新获取或明确失败；
   同时核验当前 BusyBox 支持 -a2000 和 packet socket 权限。不要去掉检查绕过错误。
4. 验证同地址续租、地址改变、短租约 T1/T2/到期恢复、AP 隔离和取消/退出，核对
   无残留客户端、不删除 eth0 配置。不能在唯一 SSH 通道无串口保底时操作。

日志位于 `/tmp/lawrec-ui.log`、`/tmp/lawrec-dhcp.log`、当前 DHCP job 的
`events.log` 和 `/tmp/wifi-autoconnect.log`。完整网络及功能交付仍待实板验收。
