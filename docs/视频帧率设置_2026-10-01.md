# 视频帧率设置与配置升级

## 实现

Settings 的 FPS 按钮切换目标输出帧率 15/30，默认 30。源采集和编码尺寸仍为
1280x720、源帧率 30；没有修改大核摄像头或当前触控诊断链路。
摘要中的 current 是当前进程配置快照，不是实测帧率。

共享 VENC0 的第一个 RTSP/录像订阅者将快照中的码率和目标帧率传给 CBR 参数；
后加入的订阅者复用同一编码器，不覆盖参数。最后一个订阅者退出后才清理。
RTSP/MP4 继续使用真实 VENC PTS，不按设置值生成时间戳。
GOP/统计周期保持原 SDK 默认行为，没有借本轮设置改变关键帧策略。

Save 二次确认并整体原子保存端口、码率、音频、分段和 FPS；改变草稿后需要重新
确认。Defaults 仅改变草稿。保存不热改当前流，重启 UI 后读取新快照。

## 配置格式与回退

`/etc/lawrec-media.conf` 的新格式要求六个字段全部存在：

```ini
version=2
rtsp_port=8554
video_bitrate_kbps=4000
record_segment_seconds=0
audio_enabled=0
video_frame_rate=30
```

- 只接受 15/30 FPS，端口 1024~65535，视频目标码率 1000~8000 kbps。
- 旧 version=1 保留端口/码率/已有音频和分段，读取为 v2 快照、FPS 默认 30；
  读取不会改写文件，下一次 Save 才写 v2。
- 新媒体文件不存在时仍兼容旧单行端口文件。未知版本/字段、重复/缺少字段和
  非法值报告错误，页面提示，进程配置采用默认值，不静默修复文件。
- 老程序不支持 v2 文件。回退程序时同时恢复备份的 v1 配置，不要只换二进制，
  否则可能退回默认端口、码率和音频策略。
- 临时文件/fsync/rename/目录同步防普通中断，不等于断电完整保证；rename 后
  目录同步失败可能已经改变文件，必须核对 pending 值再决定是否重试。

## 验证与待验收

Docker `bash tools/test.sh media-settings` 已通过，日志为
`out/fps-settings-tests.log`。覆盖 v1/v2 迁移、非法/重复/缺少字段、端口单独保存
保留 FPS/音频、重启读取、当前快照不变，以及两种订阅先后顺序和失败隔离。
编码器测试为 SDK mock，只证明参数传递和生命周期，不证明硬件实现了目标帧率。
小核 Docker 构建见 `out/fps-build.log`；页面摘要调整后的构建见
`out/fps-layout-build.log`。没有部署、切网、重启或生成新的触控 SD 镜像。

触控恢复、正常双核业务链恢复后，验收顺序：

1. 分别保存 15/30，重启 UI，查看 settings/encoder 日志中的 target_fps。
2. 分别先开 RTSP 或录像、再开另一项，确认只有一次 VENC 初始化及相同参数。
3. VLC 和导出的 MP4 分别统计实际帧数/持续时间/PTS；核对音画同步、分段首 IDR。
4. 活跃流期间保存新值，确认当前流不变，下次 UI 重启才改变。

目标帧率请求、VLC 观感和实际平均帧率是不同证据，不能仅凭日志宣布档位已验收。
