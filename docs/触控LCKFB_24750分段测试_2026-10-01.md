## 本轮变化

用户反馈 27 MHz 组改善但仍偶发鬼触。本轮在应用 LCKFB 分支中整体替换
参数，不叠加两组配置；使用用户提供的旧版兼容候选，未独立核实其官方
2025 年发布出处。保持 DSI 图案模式 `dsi_test_mode=1`。

| 参数 | 本轮值 |
| --- | --- |
| pixclk_div | 23 |
| PHY n / m / voc / hs_freq | 3 / 97 / 0x27 / 0xa5 |
| pclk / phyclk（kHz） | 24750 / 297000 |
| H total / display / sync / back / front | 552 / 480 / 8 / 32 / 32 |
| V total / display / sync / back / front | 1100 / 800 / 10 / 150 / 140 |

按 594 MHz 父时钟推算，`594000 / (23 + 1) = 24750 kHz`。本轮也改变了
消隐区，名义刷新率 `24750000 / 552 / 1100` 约 40.76 Hz，上一组约 58.78 Hz。
这些是配置推算而非实测，不能把改善单独归因于时钟降低约 8.3%。

TIMESTAMP_ONLY 内核保持不变，最终 VO enable 仍跳过。面板命令、PHY lane
硬编码、CST128 驱动、阈值、软件滤波和坐标解析都没有改。主程序仍只做
connector 初始化并等待 60 秒，不运行正常 UI/摄像头/推流/录像业务。

## 现在怎么测试

1. 完整断电上电，仍使用 TIMESTAMP_ONLY 固件，不启动 UI 或其它大核应用。
2. 小核先观察空闲状态：

   ```sh
   evtest /dev/input/event0
   ```

3. 大核串口执行，无需模型参数：

   ```sh
   /sharefs/lawrec-touch-lckfb-24750.elf
   ```

4. 确认 connector 返回 0，时序日志与上表一致，且出现：

   ```text
   [touch-test] LCKFB_24750_AB: pclk=24750 phyclk=297000; TIMESTAMP_ONLY kernel unchanged
   [touch-test] DSI_PATTERN_ON; kernel must remain TIMESTAMP_ONLY
   [touch-test] TIMESTAMP_ONLY: no VO enable
   ```

5. 观察 30～60 秒，先完全松手 10 秒，再点中央和四角，再松手观察释放。
   记录图案是否可见、无人触碰时是否持续上报、是否迟钝、DOWN/UP 是否完整。
   程序退出不恢复硬件，各组对照都需冷启动。

如文件丢失，可用 Windows CMD / PowerShell 重传，等 SCP 完成并核对 SHA256：

```powershell
scp "\\wsl$\Ubuntu\home\atlantis\lawrec\out\touch-lckfb-24750\20261001T085131Z\artifacts\lawrec-touch-lckfb-24750.elf" root@192.168.123.74:/sharefs/lawrec-touch-lckfb-24750.elf
```
