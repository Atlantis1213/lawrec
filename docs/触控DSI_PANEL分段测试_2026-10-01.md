# 触控 DSI/面板分段测试

## 前提和本轮变化

用户已确认 CLOCK/PHY 组正常，内核打印标记证明固件已生效。本轮只在该配置
之后增加 `st7701_dsi_resolution_init(info)`，依次配置 DSI、发送面板命令并
使能 DSI；480x800 分支随后打印 `DSI_PANEL_ONLY` 并返回，继续跳过 VO。
初始化函数中该 DSI 调用仅有一次，其它 ST7701 类型仍走完整初始化。

像素分频、PHY、面板命令内容和应用 `main.cc` 均未在本轮改动。应用沿用上一轮
已验证的归档 ELF，SHA256 为
`a09fcbfedae79330ce54cb38a52b1bb2db73c506c9800373b403b32cd0ba6277`。
应用里的 CLOCK_PHY_ONLY 名称仍是旧提示，以驱动新标记判断运行阶段。

## 按当前整卡测试方式操作

1. Windows 文件管理器打开目录：

   ```text
   \\wsl$\Ubuntu\home\atlantis\lawrec\out\touch-dsi-panel\20261001T070534Z\artifacts
   ```

   用 balenaEtcher 烧录 `sysimage-touch-dsi-panel.img`，保留上一轮镜像便于对照。
2. 完整断电再上电，保持 UI 关闭。整卡重刷会清除以前 SCP 到 sharefs 的程序，
   因此从上述目录重新传入同一个 ELF 到 `/sharefs/lawrec-touch-clock-phy.elf`。
3. 小核先执行：

   ```sh
   chmod +x /sharefs/lawrec-touch-clock-phy.elf
   evtest /dev/input/event0
   ```

4. 大核串口执行：

   ```sh
   /sharefs/lawrec-touch-clock-phy.elf
   ```

   必须出现：

   ```text
   [touch-test] DSI_PANEL_ONLY: skip VO, ret=0
   ```

先松手观察 10 秒，点按中央和四角，再松手观察。记录触点是否无接触持续上报、
实际点击是否迟钝、是否正常释放。程序观察 60 秒后退出，但硬件配置可能保持，
切换阶段必须冷启动；屏幕亮或黑都不能替代触控事件作为结论。

## 结果如何解释

| 结果 | 下一步 |
| --- | --- |
| 异常复现 | 拆分 DSI 属性设置、面板命令与 DSI 使能 |
| 仍正常 | 下一轮加入 VO 初始化和扫描 |
| ret 非零或缺少新标记 | 先核对固件与初始化结果，不能得出阶段结论 |

PHY 已配置但不传输，与 DSI 工作时的状态不同；本轮保持频率不变，并不意味着
已排除时钟相关干扰。此测试不运行摄像头、IPC、推流或录像业务。
