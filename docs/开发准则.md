# K230 执法仪项目开发准则

## 1. 编译环境

- 一律使用 Docker 编译。
- 禁止在主环境直接执行会改写 `output/` 产物的本地编译命令。
- 标准 Docker 镜像使用 `ghcr.io/kendryte/k230_sdk`。
- 进入编译环境统一使用：
  - `./tools/docker/enter.sh`
- 执行编译统一使用：
  - `./tools/docker/build.sh CONF=k230_canmv_lckfb_defconfig`
- 顶层 `Makefile` 已增加 Docker 强校验；若不在容器内，构建应直接失败。
- 如需切换镜像，不直接改脚本，使用环境变量：
  - `K230_DOCKER_IMAGE=<your-image>`

## 2. 镜像产物校验

- 不能只看 `make` 成功，必须校验镜像内实际内容。
- 对 little rootfs，至少校验：
  - `/app/lawrec/ui/ui`
  - `/usr/lib/liblv_drivers.so`
  - `/etc/init.d/S99lawrec`
  - `/etc/init.d/S50sshd`
- 必须确认 `rootfs.ext4` 内保留基础目录：
  - `/dev`
  - `/proc`
  - `/mnt`

## 3. rootfs 重封装规则

- 如需手工回填 little rootfs，基底必须来自 `rootfs.cpio`。
- 覆盖顺序固定为：
  1. `output/.../little/linux/rootfs/`
  2. `output/.../little/buildroot-ext/target/`
  3. `board/common/post_copy_rootfs/`
- 不能使用会破坏根文件系统骨架的做法，例如：
  - 直接对已展开 rootfs 执行错误的 `rsync --delete`
  - 删除 `/dev/null`
  - 删除 `/dev/console`

## 4. 启动脚本规则

- 所有 `/etc/init.d/S*` 脚本必须保持可执行权限 `755`。
- `S50sshd` 只能在 host key 缺失时生成 key，不能每次启动都无条件生成。
- `S99lawrec` 必须保持当前收敛逻辑：
  - 不再自动启动 `touch_emu`
  - 若发现 legacy `touch_emu` 在运行，则先停掉

## 5. 触控与字体规则

- 庐山派触控当前基线固定为：
  - 驱动：`edt_ft5x06`
  - 设备：`/dev/input/event1`
- 不能再把 `touch_emu` 当成正式输入源。
- FT5x06 触控状态判断不能只依赖 `BTN_TOUCH`，必须同时处理：
  - `ABS_MT_POSITION_X`
  - `ABS_MT_POSITION_Y`
  - `ABS_MT_TRACKING_ID`
  - `SYN_REPORT`
- 如果出现“没点也触发”“松手后仍判定按下”，优先检查 `ABS_MT_TRACKING_ID == -1` 的释放路径。
- 中文显示出现方框时，优先怀疑字库 glyph 覆盖不足，不要先误判成 UTF-8 编码问题。
- `lawrec` 当前菜单页必须随镜像一起带上自定义精简字体：
  - `src/little/buildroot-ext/package/lawrec/src/ui/src/lawrec_font_cn_16.c`

## 6. 提交显示链相关修改

- little 侧显示问题优先走 `door_lock` 已验证路径。
- 非必要不扩展 little DRM 策略，不随意新增自动 plane 选择或 full modeset 行为。
- big/little 显示职责边界：
  - big: panel/mode owner
  - little: overlay plane client
