# 离线开发包与构建追溯

目的：把当前 M0～M5 软件增量形成一致的板端验收输入，而不是继续沿用 09-29
“互斥/没有回放”的旧包说明。本轮不安装、不联网、不改启动开关或内核。

## 构建方式

```bash
bash tools/test.sh package
bash tools/package.sh --snapshot
```

测试及大小核编译只在 Docker 内执行。打包中的文件复制、哈希、压缩不编译
代码。默认不带参数的 `package.sh` 仍要求干净已提交工作区并执行完整软件测试；
`--snapshot` 用于当前未提交开发状态，只做定向打包检查和双核构建，明确标记
开发包、未板端验收，不自动 Git 提交/推送，不把它当成正式版本。
打包期间不要编辑源码；内容、文件集合或权限变化会拒绝发布。

## 包含内容

| 位置 | 用途 |
| --- | --- |
| `app/lawrec/ui/` | 小核 UI/control/RTSP/录像/回放单进程与界面资源 |
| `lawrec.elf` | 匹配的 RT-Smart 大核应用，不是内核 |
| `lib/` | 配套 `liblvgl.so`、`liblv_drivers.so`，保留当前触控映射 |
| `etc/init.d/` | S99lawrec 与依赖 UI headless 模式的 S45wifi |
| `source.tar.gz` / `source/` | 实际构建时的源码快照、哈希、权限和 Git 状态；不含 `.git`/输出/忽略的本地凭据 |
| `sdk-inputs/` | 配置、README、ST7701、connector、DT、触控驱动、SDK 编译/链接脚本的选定快照 |
| `evidence/` | 此次实际执行的测试、双核构建及 ELF 检查日志 |
| `BUILD.txt` | 基础提交、源码摘要、SDK 状态、Docker ID、测试范围和内核前提 |
| `SHA256SUMS` / `verify.sh` | 内容/关键执行权限/缺失或额外文件/符号链接检查；只验证，不安装 |

库会解引用复制，避免符号链接指向包外旧库；启动脚本必须与 SDK target 中的
当前脚本字节一致。既验证暂存包，也实际解压压缩包检查；源码快照另行解压
读回校验，失败包不会被发布到 `out/releases/`。

当前 SDK 缺少 Git 元数据，记录为 `unavailable-unversioned-sdk`，不能伪造上游
版本号。选定输入的哈希不是完整 SDK 的身份或全量归档；依旧需要单独保留
完整 SDK、工具链、模型和已通过触控的内核/整卡固件。应用包不能替代 SD 镜像。
验证器执行 shell 来自可信源码包；哈希不是来源认证，不能运行陌生包的脚本。

## CMake 重复编译修复

原 SDK toolchain 会追加 ISA/ABI 参数，业务 CMake 又把追加后的 C flags 强制写回
缓存，并覆盖 CXX flags。反复配置后，同一组选项积累数十次；编译命令每次
变化，导致没有源码改动也重新编译整个大核。

现在只移除这四个已知重复项，保留其他 C/CXX 用户参数，在 target 编译与链接
各设置一次 `-fopenmp -march=rv64imafdcv -mabi=lp64d -mcmodel=medany`。链接端
使用兼容 CMake 3.2 的 LINK_FLAGS，保留驱动的 OpenMP/ABI/运行库选择，不改
SDK 或业务算法。连续两次 Docker 构建验证：第二次无编译/链接步骤，仅检查
已有目标；CMakeCache 不再积累参数。日志 `out/big-idempotent-{first,second}.log`。

## 大核 ELF 历史告警

主机 GNU readelf 与 Docker 版本分别报告：

```text
Section 5260 has invalid sh_entsize of 8
Section 5260 has invalid sh_entsize of 0000000000000008
```

实际对应 `.got`，类型为 RELA，entry-size 为 8，而普通 ELF64 RELA 预期为 24。
先前已归档的 `out/touch-ui/20261001T155329Z/artifacts/lawrec.elf` 同样存在此问题，
不是本轮打包或 CMake 清理参数新引入。当前应用为 ET_EXEC；本地 SDK 的
`components/lwp/lwp.c` 以 PT_LOAD 读入，用户态映射分支按 SHF_ALLOC 覆盖该节；
`.got` 动态重定位处理限于 ET_DYN，也未使用 `sh_entsize`。

以上是本地源码与归档文件证据，不是实际烧录加载器版本的证明。为避免改变
RT-Smart/GOT 布局，本轮不改链接脚本、不修补 ELF。验证工具只允许这两条
精确诊断，且复核该节确为 `.got`/RELA；任何其它诊断、错误架构/ABI/类型都
拒绝发布。告警写入随包 `evidence/elf-check.log`，真实加载/媒体运行仍需板测。

## 当前验证与下一步

Docker 包装定向测试覆盖源码内容/权限/文件集合变化、凭据/符号链接拒绝、
SDK 输入变化、陈旧启动脚本、篡改/额外文件/丢失权限、压缩后读回和主机
原生 ELF 拒绝。实际开发包验证大小核及两库为 ELF64 小端 RISC-V LP64D。
这些检查不重复做网络/媒体硬件验收；已有功能测试证据保留在相应开发记录。

最新版应用包路径、校验值见《当前状态》；安装仅在确认内核、保存旧程序和
拥有串口恢复条件时按 [部署说明](v1_验收与部署.md) 手动执行。新包需核对两核
启动、触控、预览、并发推流/录像、文件回放、音频和长测；网络自动冲突恢复
与未分段内存保护的策略仍待确认，不能将本轮交付输入当成全部目标已完成。
