# 触控 CLOCK/PHY 分段测试

## 本轮已完成

2026-10-01 用户确认整卡更新、冷启动后 CLOCK/PHY 组正常，且内核输出
`CLOCK_PHY_ONLY` 标记。只说明这个阶段尚未触发异常；DSI 开始传输后是否存在
时钟相关干扰仍待验证。下一阶段已构建，见
[DSI/面板分段测试](触控DSI_PANEL分段测试_2026-10-01.md)。
以下保留 CLOCK/PHY 阶段历史配置和操作，当前 SDK 已切换到 DSI/面板阶段。

## 定位进度

- 本对话板测：大核未启动时空闲无事件；大核初始化后、不碰屏幕且 UI 未启动，
  10 秒内触控 IRQ 增加 597，evtest 记录 67 帧事件。用户确认未接触屏幕。
- 禁用 UI 触摸读取仍有异常。I2C tracepoint 抓到 267 个回复包，数量均为 1，
  所有传输返回 2（两条消息完成），坐标约为 (237,344)，未用 i2cget 抢总线。
  证明这一轮异常并非单纯 Linux 没释放旧槽；不等于已证明电气干扰的具体来源。
- 显示不变时重新绑定内核触控驱动，10 秒无包，随后至少捕获一次正常 DOWN/UP。
  重启 UI 后再次持续 PR，用户确认界面无响应；复位不是已验证的永久解决方案。
- 用户另一轮测试反馈：power/reset/backlight 单独运行正常，connector init 后异常。
  本轮沿此结果做下一阶段拆分，尚未独立复测该 power-only 结论。

## CLOCK/PHY 阶段修改

1. 保留用户在 `big/main.cc` 的 connector-only 测试和 60 秒观察窗口。
   应用已恢复调用 connector init，本轮仅补测试版本标识及分频/PHY 参数日志。
2. SDK `src/big/mpp/kernel/connector/src/st7701.c` 在设置 PHY 后，对
   `ST7701_V1_MIPI_2LAN_480X800_30FPS` 打印标识并提前返回。
3. 实际执行包含 power/reset、pixclk、command buffer count、PHY。
   不调用 `st7701_dsi_resolution_init()` 和 `st7701_vo_resolution_init()`。
   因此不是绝对只有两个寄存器操作；若仍异常，command buffer 设置也要拆分。
4. 临时截断不会主动关闭之前已运行的 DSI/VO；每轮必须完整断电重启，
   并确保没有其它程序在测试前初始化显示。不能通过重复运行 ELF 清除旧状态。

业务 ELF 的退出只结束进程，不保证恢复硬件。60 秒结束后的 IRQ/触点状态仍需记录。
驱动原始源文件备份在 `out/touch-clock-phy/source-backup/st7701.c`，恢复时优先
只撤销本轮条件提前返回，不覆盖他人后续修改。

## 构建与产物

唯一入口（Docker）：

```sh
bash tools/build.sh touch-clock-phy
```

该目标使用现有 SDK，顺序为 prepare_memory、mpp-kernel、big-core-opensbi、
业务 ELF、build-image。未运行 Linux 编译/配置目标，也未替换 Linux 触控驱动。
build-image 会从当前 SDK 来源重新打包 Linux DTB/rootfs；为了避免其它变量，
本次板测优先只更新 RTT 固件，保留板端 Linux、rootfs 和触控适配。

旧 SDK staging 存在 root 文件，此诊断目标在 root Docker 容器中打包，最后将
本轮输出和项目 out/big 归还宿主用户。普通 little/big 构建仍使用宿主 UID。

## 板端最小测试

不要直接把固件写到未经核对的块设备。先核对当前卡的分区布局并备份 RTT；
本轮尚未执行刷写。单独 SCP 应用 ELF **不会更新内核驱动**。

将诊断 ELF 传入小核 `/sharefs/lawrec-touch-clock-phy.elf`，确认权限可执行。
更新 RTT 固件后完整断电上电，关闭小核 UI，不运行普通 lawrec/显示 demo。
小核先启动（先从 input devices 核对 event0 为触控）：

```sh
evtest /dev/input/event0
```

先观察未启动测试程序时的空闲和点击，再在大核串口执行：

```sh
/sharefs/lawrec-touch-clock-phy.elf
```

必须从**内核**看到：

```text
[touch-test] CLOCK_PHY_ONLY: skip DSI/panel/VO, ret=0
```

应用的 `require CLOCK_PHY_ONLY firmware` 只是提示，不是内核已更新的证据。
这轮允许黑屏，判断依据是 evtest：先松手，再点三次，再松手，记录是否有
持续触点和是否完整释放。不要启动 UI 补亮屏，否则破坏阶段隔离。

## 结果分支与恢复

- CLOCK/PHY 阶段异常：进一步分别检查 pixclk、command buffer、PHY。
- CLOCK/PHY 正常：下一轮添加 DSI/面板阶段，仍先跳过 VO。
- 添加 DSI 正常、VO 后异常：查持续扫描/传输与中断；不能仅凭此就断定频率错误。

每次更改驱动都重新构建 RTT；每次测试都冷启动。最终要撤销 SDK 的提前返回，
恢复 main 的业务入口并重新构建，验证完整显示与触控同时正常后才能发布。
本轮未刷机、未声称鬼触已解决，也没有调整频率、面板参数或添加软件滤波。
