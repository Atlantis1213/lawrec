# 录像停止音频尾帧保护

本文保留上一增量的包级收尾记录。后续已加入包内裁剪、IDR 等待与末样本时长，
当前实现请结合 [录像分段音频同步与 MP4 时长](录像分段音频同步与MP4时长_2026-10-02.md)。

## 修复的问题

原收尾先 `close()` 清空视频和音频队列，再注销采集。音频虽然已进入队列，
却可能还没由录像 worker 写入，特别是短录像和视频、音频回调到达顺序不同的
场景。普通音频写入函数遇到 stop 标记也直接返回，使收尾无法补写尾帧。

本轮只完善正常停止，不修改显示时钟、PHY、面板序列、触摸驱动或音频默认开关。

## 当前收尾顺序

1. 冻结最后成功写入的视频微秒 PTS，丢弃未接受的视频队列尾部。
2. 注销录像视频订阅。其它 RTSP 订阅仍拥有共享编码器。
3. 正常停止且没有先前错误时，音频目标边界为最后视频 PTS 加一个名义帧周期。
   帧周期取当前进程已冻结的 15/30 FPS 配置，不取设置页尚未生效的草稿。
4. 由同一个录像 worker 补写音频，最多等待约 250 ms 的迟到数据。等待队列时
   不持有录像状态锁，UI 查询和停止请求不会被这段等待锁住。
5. 音频注销在回调锁内解除订阅并 `finish()` 队列：禁止新投递，保留已有帧。
   在回调锁外执行 SDK stop/unregister；RTSP 仍订阅时不停止共享 AI/AENC。
6. 检查剩余投递错误、清空边界以外的数据，再关闭 MP4。仅所有步骤成功才
   发布 `.mp4`；失败保留 `.part` 和首次错误，不能用清理错误覆盖最初原因。

已有录制错误、启动失败、异常退出或视频注销失败不走正常尾帧等待。尾帧写入
失败、队列溢出、时间戳/数据非法、等待超时、SDK 清理失败、MP4 关闭失败都
阻止发布。日志包含音频边界、最后包结束 PTS、包数及具体错误码。

## 已知精度与未完成项

G.711A 单声道 8 kHz 按一字节一个样本估算，125 微秒/字节；输入至多 320
字节，与回放路径一致。该估算假定 SDK PTS 指向包首样本，仍需实板确认。

本轮保留完整音频包，不裁剪样本。因此最后一个包可能比视频停止边界多出
不足 40 ms；不能声称样本级精确同步。MP4 SDK 仍有毫秒换算及末样本时长
估算，名义 FPS 也不是硬件实测帧率。应用等待有界不等于 SDK stop 或文件系统
调用具备硬超时。

仍需继续完善：分段 IDR 附近迟到音频等待、跨段包拆分/段首裁剪、MP4 末样本
时长元数据，然后实板核对 AI/VENC 时钟同源、麦克风、VLC、本地回放和长录。
当前不能将“队列尾帧不再直接丢弃”表述为“音画同步已全部完成”。

## 精简验证

通过 Docker 复用一个定向入口，不重复执行整套网络与媒体验收：

```bash
bash tools/test.sh record-io
bash tools/build.sh little
bash tools/render-ui.sh out/ui-preview/after
```

覆盖队列保留/封闭/错误粘性、停止后补写、30 FPS 短录像、15 FPS 迟到两个音频
包、等待期间 UI 状态锁可用、未来包不算完整尾部、超时、溢出、非法长度、写入
失败、清理失败与首次错误保留；共享音频测试确认录像注销不停止 RTSP。
同时保留原真实 SDK MP4 写入/读回及故障测试。视频顺序检查使用微秒，包含同
一毫秒内倒序的回归用例。

构建和测试日志：`out/audio-tail-tests.log`、`out/audio-tail-build.log`。
设置页真实 LVGL 渲染与键盘/确认框检查：`out/ui-preview-after.log`；输入来自
固定模拟状态，不是实板截图。本轮未部署、未连接或重启开发板、未生成 SD 镜像。
